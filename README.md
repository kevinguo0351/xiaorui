# 小瑞 · Mac 本地生活助手

**小瑞，让老人说句话，就能更自主地安排生活。**

很多老人知道自己想去哪里、想吃什么，也能自己出门和上车，但手机里的叫车、点餐和支付流程成了生活中的门槛。小瑞是一位面向老年人的个人生活助手：通过自然口语、记得住的个人偏好和真实生活服务，帮助老人去想去的地方、吃想吃的饭，减少对复杂手机操作和子女即时协助的依赖。

理想的使用方式是：子女前期协助设置家庭地址、常用地点、熟悉餐厅和必要账号，老人日常通过说话表达需求；小瑞补问必要信息、说明真实选择，在消费前讲清内容和金额并取得确认，办完后反馈实际结果。在事先同意的范围内，小瑞还可以在午饭时间询问是否需要订餐，或按约定提醒服药，日常提醒计划接入苹果提醒事项 App。

上述是产品方向，尚未全部实现。当前已接入真实 Agent 运行时、持久会话和显式个人资料管理，用麦当劳的「真实菜单与报价 → 明确确认 → 受控执行」流程验证生活服务链路；独立实验已创建真实待支付订单，网页与全程语音交易仍待验收。完整理念、理想态与阶段边界见 [产品理念与理想态](docs/product-identity.md)。

首版服务范围已确定为**北京：瑞幸、麦当劳、滴滴**。瑞幸和滴滴已加入聊天工具循环的查询适配层；真实联调状态见当前范围文档，不代表已经能下单、付款或叫到车。麦当劳现有联调仍是到店自取，麦乐送到家是下一阶段目标。

三场景现已整合到同一个 Agent：地点／门店／商品选择卡片 → 真实核价 → 具体方案 → 语音或页面明确二次确认 → 宿主执行和本人订单状态查询。模型只能提案，不能直接下单。新增共享 SQLite 操作台账，确认前重核价，方案变化后重新确认；超时、重复点击、重启不会自动重放订单。当前真实交易执行全部关闭，避免开发验收触发订单和滴滴免密扣款。

覆盖与限制分别见 [滴滴](docs/didi-scenario.md)、[麦当劳](docs/mcd-scenario.md)、[瑞幸](docs/luckin-scenario.md)。当前支持按场景查询、修改候选、核价、准备方案、本人记录与进度、取消条件检查；没有平台支持证据的取消／退款／改已提交订单会明确拒绝。闭店、缺地址、超预算、未取得报价和未知订单都不能伪装成功。自动定位、语音唤醒和常驻后台通知尚未完成；当前位置缺失时仍需老人说出地标。网页进度轮询只在页面打开时工作。

目前已通过麦当劳官方 MCP 的真实门店、菜单、套餐详情和核价联调。独立实验经用户确认后已创建一笔真实待支付订单并打开官方扫码支付页，未付款；网页下单默认关闭，网页完整交易与语音闭环尚待验收。网页 Agent 已接入固定版本 nanobot，具备持久会话、稳定个人工作区、明确保存／修改／忘记资料、任务记录和只读查询、基础调度生命周期；真实跨进程验收见 [底座整合说明](docs/foundation-integration.md)。

## 本地启动

可双击 `启动.command` 启动。需要 macOS、[uv](https://docs.astral.sh/uv/)；源码构建前端还需要 Node.js/npm。首次配置凭证后再启动；下面是手动启动步骤。

```sh
cp .env.example .env
```

已有 `.env` 时直接编辑，不要覆盖现有凭证。填写麦当劳 Token 后：

```sh
uv sync
cd frontend
npm install
npm run build
cd ..
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>。若下载的交付版本已包含 `frontend/dist`，可跳过 Node.js 安装与前端构建。项目提供启动入口时，以启动脚本提示为准；首次下载依赖需要网络。

开发前端时可以在 `frontend` 中运行 `npm run dev`，其 `/api` 请求代理到本机 8000 端口。

## 配置

凭证仅放本机 `.env`，不提交 GitHub、不粘贴到聊天或日志。

| 变量 | 用途 |
| --- | --- |
| `MCD_MCP_TOKEN` | 麦当劳官方 MCP 的账号凭证，网页真实查询必需 |
| `MCD_ORDER_ENABLED` | 默认 `false`；只有明确要测试真实订单时才开启 |
| `LUCKIN_MCP_TOKEN` | 瑞幸官方 MCP Token，用于查门店、饮品和订单预览 |
| `DIDI_MCP_KEY` | 滴滴官方 MCP Key，用于北京地点搜索和车费预估；直接叫车权限需另行核实 |
| `LUCKIN_ORDER_ENABLED` | 默认 `false`；家人配置后才允许明确确认的瑞幸订单执行；已有未知请求仍会阻止新单 |
| `DIDI_ORDER_ENABLED` | 默认 `false`；开启后“确认叫车”可能真实叫车并由关联账户免密扣款 |
| `ARK_API_KEY` | 网页对话 Agent 的文本模型凭证 |
| `ARK_BASE_URL` | 火山方舟调用地址，以账号地域为准 |
| `ARK_MODEL` | 已开通模型 ID 或调用示例中的 Endpoint ID |
| `ARK_CONTEXT_WINDOW_TOKENS` | 本地上下文预算，默认 64000，须不超过所用模型支持长度；包含工具与系统说明 |

在 [麦当劳官方 MCP 平台](https://open.mcd.cn/mcp) 登录手机号，进入控制台，按协议激活并复制 Token。服务地址和能力以 [官方指南](https://github.com/M-China/mcd-mcp-server) 及账号实际发现的工具为准。

瑞幸在 [官方 AI 开放平台](https://open.lkcoffee.com/mcp) 登录后获取 Token；滴滴在 [官方 MCP 平台](https://mcp.didichuxing.com/) 激活 Key。由家人在本机配置，老人不需要处理凭据。瑞幸外送、两者的交易与支付均未验收；当前没有对模型开放它们的创建订单、取消订单或支付工具。

三场景的准备工具会播报具体方案。只有紧接着说“确认叫车”“确认下单”或“确认取消”，或在当前卡片点击对应按钮，才进入宿主确认入口；“好的”和模型／工具返回文字不构成确认。说“先不下单”“先不叫车”“取消方案”只取消本地方案。任何修改或新询问都会使旧交易方案失效，需要重新准备。启用执行开关前，应以确有需求的一笔订单／行程进行最终人工验收；开发、测试、启动服务不构成订单授权。

填写凭据后可运行只发现工具、不发起业务写操作的检查：

```sh
uv run python experiments/life_services_probe.py luckin
uv run python experiments/life_services_probe.py didi
```

然后可在聊天中说“帮我看看北京国贸附近的瑞幸，有什么拿铁”，或“查一下从北京国贸到北京西站打车大概多少钱”。查询会真实访问服务；地点、门店和商品由用户确认。没有自动定位时先询问地点；瑞幸需要真实经纬度，可使用本轮滴滴地点搜索取得的坐标。候选卡片、方案卡片和宿主确认已接入，但不能视为三平台真实交易已经全部验收。

火山模型在 [火山方舟控制台](https://console.volcengine.com/ark) 开通并创建 API Key。文本模型、语音识别、语音合成的权限和配置需分别核实。高德及苹果提醒事项尚未接入网页，目前无需为此配置额外凭证。

豆包语音开通、配置变量与验收限制见 [语音接入说明](docs/voice-integration.md)。需要独立的 `DOUBAO_SPEECH_API_KEY`，不能以方舟文本 Key 代替。缺少语音 Key 时仍可打字，不会使用假识别结果。

## 当前使用流程

联系人式交流正在落地：输入框可在小瑞处理时继续发送。左侧保留文字／单条语音输入切换，右侧加号展开图片和语音通话；持续通话支持实时字幕、插话停止播报和通话中打字。当前实现、测试证据与真实模型额度阻塞见 [联系人式交流验收](docs/contact-experience.md)，新通话体验和真实看图仍待验收。

1. 在底部输入框输入“帮我买份麦当劳，35 元以内”，小瑞处理时仍可继续发送补充。左侧切换语音输入后，点击开始、再次点击停止提交；需要持续通话时，点右侧加号 → 语音通话，停顿后自动提交，结束时点击“挂断”。加号 → 图片可选择并预览图片，再点击“发送”。
2. 小瑞通过模型补问城市和附近地点，调用真实门店搜索；这里不是自动定位。
3. 查看至多三张经真实核价的套餐卡片，用自然语言说“选第二份”，或点击卡片。不足三份不会凑数。
4. 选定后重新核价并展示确认方案，核对取餐门店与金额，再按页面进行明确确认。

也可以说“请记住我的称呼是……”“查看已保存的资料”“忘记我的称呼”。明确保存的个人资料跨新聊天与服务重启保留；临时对话不会自动变成永久偏好。“查看最近任务记录”查询实际执行状态，不能自动重放中断任务。基础调度已运行，但当前没有用户定时提醒或通知投递。

网页对话由运行时与宿主共同管理：模型会话、展示记录、个人资料及任务状态分层保存。新对话只重置当前线程，个人资料独立管理。具体已通过的恢复与资料操作验收见底座整合说明。详细边界见 [Agent 接入说明](docs/agent-integration.md)。豆包语音真实合成音频经流式识别取得最终转录的闭环已通过；浏览器真人麦克风体验仍待验收。

未开启订单执行时，页面可查询与核价，但不能创建订单，也不会显示虚假的「下单成功」。开启执行后，确认操作可能创建真实待支付订单；创建成功不等于支付成功。

价格和可售状态会变化。提交前重新核价，变化后重新确认。提交超时或重启遇到执行中订单时，按「结果未知」处理，不能盲目重复下单。
