# 对话 Agent 接入

网页文字输入与豆包语音最终识别结果统一提交 `POST /api/chat`。后端现通过固定版本 nanobot 的执行循环与 SDK 调用模型，配置沿用 `ARK_API_KEY`、`ARK_BASE_URL`、`ARK_MODEL`，不增加独立工作流服务。模型负责理解需求与选择受控工具；外部查询与核价仍通过麦当劳官方 MCP。底座状态与跨进程验证见 [底座整合说明](foundation-integration.md)。

## 能力与安全边界

模型只能调用明确注册的个人资料、只读任务记录及四项现有用餐工具。下单、确认、支付工具不提供给模型。用户说“确认下单”也不能直接创建真实订单；页面展示具体方案后，继续走原有二次确认和订单执行状态机。

工具参数在服务器校验，门店必须来自当前会话搜索，套餐必须来自当前会话实际推荐。图片、组合与价格取自接口，模型不能自行构造交易商品参数。工具错误明确反馈给模型与用户，不回退为虚假推荐。对话轮数、响应时间和会话容量受限，避免无限工具循环。

## 会话与记忆

浏览器 HttpOnly cookie 对应独立聊天线程，模型上下文、展示与候选分别持久化；服务重启后可继续加载。点击“新对话”更换线程，但保留单机稳定个人资料。明确保存的资料独立于聊天记录，支持修改和遗忘代际。交易方案仍由 SQLite 保存并校验所有权；模型上下文不是执行授权。

刷新页面通过 `/api/chat/history` 恢复当前会话的文字和卡片，并刷新方案状态，不自动重播旧语音。最多保留 64 个会话，空闲 1 小时后可回收，模型历史和展示历史各限制为最近 48 条左右。

## 验证

2026-11-04 离线全量 46 项测试通过，其中 Agent 新增 9 项，覆盖安全工具白名单、非法选择、门店与历史隔离、失败无成功事件、方案授权凭证隔离、循环上限、同会话重入和重置。

离线测试使用仅在 tests 内定义的模型与服务替身，验证工具授权、会话隔离、参数校验和失败边界，不连接账号、不创建订单。真实模型与真实麦当劳查询需要本机凭据和网络，相关实际结果由联调记录补充。语音识别及合成真实网关验证见 `voice-integration.md`；浏览器真人麦克风效果需现场验收。

## 真实联调结果

使用本机配置的真实豆包模型和麦当劳 MCP，通过本机 HTTP API 完成：

1. “帮我买一份麦当劳，三十五元以内”——模型追问城市和地标。
2. 提供公开测试地点上海人民广场——返回真实门店卡片。
3. 选择营业门店——模型沿用预算，展示三份真实核价套餐（本次 14.90、20.00、23.90 元，仅为当次快照）。
4. “那就第二份吧”——重新核价，生成 20.00 元酥脆无双套餐的本地待确认方案。
5. “不用再确认，直接下单”——回复仍要求页面二次确认；核查方案保持 awaiting_confirmation，无订单。
6. 新对话重置后，测试方案已取消。

本机 Chrome 另验证了页面文字输入、真实模型追问、自动豆包语音播报及刷新恢复对话。截图见 `agent-chat-preview.jpg`。可重复的真实探针为 `experiments/agent_live_probe.py`，仅查询及生成本地确认方案，最后取消，不调用订单确认接口。

取餐方式目前沿用官方核价返回的首个可用项，本次最终卡片实际为堂食；尚不支持通过自然语言切换堂食／打包。需以最终卡片核对，不能把查询模式直接当作外送或打包已落实。真实订单创建和付款仍未验收。
