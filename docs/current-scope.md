# 当前范围与验收

## 产品方向与当前交付（2026-11-05）

小瑞的整体定位是面向老年人的 Personal Agent：通过自然语音，像一个熟悉老人、耐心帮忙的年轻人在身边，帮助跨过打车、点餐等数字操作门槛；通过长期记忆延续习惯与兴趣，并在合适的时候主动交流。完整定义见 [产品理念与理想态](product-identity.md)。

当前已有真实 Agent、显式个人资料管理、持久会话、生活服务查询与确认层，以及联系人式输入和自然播报。语音正文分离已通过真实模型与 HTTP 链路验证，模型接口已在 2026-11-05 恢复调用；下文 2026-11-04 的额度阻塞和测试数量均为当时快照。最近一轮全量离线记录为 146 项 Python 测试与 5 项前端录音／通话测试通过，并不替代真人和真实交易验收。

新增理想态包含主动了解偏好、习惯与兴趣记忆、适时主动提议，以及抖音视频推荐和喜欢作品的故事分享。**这些方向本轮只写入产品规划，尚未实现或验收**；当前 Cron 引擎存在也不代表主动提醒或内容推送已接通。

后续按以下层次推进，具体服务仍逐项验收：

1. 先完善语音听感、接话时延与真实生活服务闭环，确保能可靠办事。
2. 完善记忆与任务管理，让地址、偏好、习惯和兴趣有明确来源、可确认、可纠正，临时要求与长期事实分开。
3. 在老人同意的范围内接入主动询问、提醒和通知，提供时间、频率、安静时段与暂停控制。
4. 接入有真实来源的内容服务，先介绍、愿意听再展开，并根据反馈调整推荐与记忆；抖音是待验证的候选渠道。

主动提议由老人决定是否继续；消费仍需绑定具体方案确认。以下保留各阶段真实记录，不将新增产品方向算作已完成能力。

## 最新范围决定：北京三项服务

### 三平台支付入口实测（2026-11-04）

用户逐项确认瑞幸东华门大街店拿铁 1 杯 9.90 元（自取）与麦当劳北京新东安二号餐厅麦香鱼 1 个 22 元（堂食），仅创建待支付订单、查看支付入口，不付款；滴滴只检查入口，不发单。以下是独立受控实验，不代表网页交易流程和全程语音已经验收。

- 麦当劳：重新核价后创建订单成功，取得官方 `payH5Url`；随后真实 `query-order` 确认为待支付（status 10）、金额 22 元。Chrome 视觉核实页面显示“扫码进入麦当劳 APP 支付”，有二维码，尚未支付。修复了原适配器未识别 `payH5Url` 的问题，并增加回归测试。私有订单号与支付链接只保留在 `.local-data/payment-probe/mcd.json`，不写入公开文档。
- 瑞幸：重新核价后发出一次创建请求，但结果无法确认，未取得可核实的订单号／支付入口。执行记录保持 `unknown`，禁止自动重试；用户查看瑞幸小程序表示没有订单。官方当前只提供按订单号查询，没有发现最近订单列表，无法仅靠 MCP 排除延迟创建或账号差异。后续提交程序已补上先持久化响应、再解析的保护，防止陌生响应形状导致诊断证据丢失。
- 滴滴：真实生成官方打车跳转链接，未发单。当前账号官方控制台明确提示关联手机号使用 MCP 叫车时将通过个人账户免密支付；这不是独立收银台工具，不能把“查看支付页”当作不产生叫车的步骤。控制台说明不等于扣款实测，真实叫车和支付均待验收。
- 实验入口：`experiments/payment_probe.py` 仅查询、核价和生成跳转链接；`payment_submit.py` 只接受具体已确认方案的 digest，重新核价、文件独占锁和落盘的 submitting／unknown 状态防止重复提交。没有支付工具或滴滴发单分支。68 项离线测试通过。
