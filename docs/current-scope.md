# 当前范围与验收

## 本阶段

Mac 本地网页，单用户，极简聊天入口，门店、套餐推荐与订单确认卡片嵌入聊天记录。此前的侧栏任务页设计已由用户确认替换。首先验证到店自取，再扩展外送；真实外部数据查询失败时明确报错，不以假菜单、假价格或假订单替代。

已实现的产品切片：真实门店和菜单、套餐选项、核价、待确认方案、后端确认控制和防重复执行。网页中尚无完整语音个人助手。

聊天已接入豆包文本模型工具调用，通过自然语言补问地点、搜索门店和选择套餐；刷新恢复当前会话的文字与卡片，Agent 短期上下文保存在有界服务内存中，服务重启或会话回收后不保留。推荐接口使用实际菜单、明确默认组合和官方核价，返回至多三张 A/B/C 图片卡片及 speech_text；豆包实时识别与语音合成网关已接入，真实合成音频回送流式识别获得最终转录的链路通过，真人浏览器麦克风效果待验收。推荐不会创建待确认订单，选定后才重新核价生成确认方案。

## 本地离线验证

2026-11-04 使用 `.venv/bin/python -m unittest discover -s tests -v` 通过 46 项测试（包含交易、推荐、语音和 Agent 边界），覆盖并发确认的一次性认领、会话所有权、有效期、错误版本／凭证、请求篡改、取消／替换、重启恢复、报价变化重新确认、取餐方式变化、超时结果未知及默认关闭下单。另通过实际 ASGI 请求检查 Host／Origin 边界、非 JSON 写请求拒绝，以及数量／确认版本不能用布尔值替代整数。测试使用临时数据库和测试专用服务适配器；不读取真实凭证，不触发官方订单。

## 已有真实接口证据

2026-11-04，官方麦当劳 MCP 工具发现和只读链路通过。公开测试地点上海人民广场返回 5 家门店；测试门店菜单返回 52 个商品；套餐详情和核价通过，默认板烧鸡腿堡三件套为 34.50 元。这是当次快照，不是永久菜单或当前报价承诺。

nanobot 与豆包文本模型的独立实验已验证模型选择本地资料工具、真实文件写入，以及新进程、新对话读取偏好。Responses 工具回传存在兼容问题，Chat Completions 路径通过。这些实验没有接入网页，也不证明自动记忆、忘记与任务恢复已经完成。

## 交易验收尚待完成

A1：用户核对门店、商品、取餐方式、总价并二次确认后，真实创建订单，取得订单号与官方支付入口。付款由用户在官方页面完成。无论有没有支付，不得未经确认创建订单。

验证顺序：确认状态机离线边界 → 本地网页真实报价 → 审阅具体方案 → 明确确认 → 创建一笔真实待支付订单 → 查询确认结果。运行测试和启动服务不构成交易授权。
