# 瑞幸老人任务场景

实现入口为 `app/luckin_scenario.py`，不修改共享宿主。接入官方 MCP，由宿主提供持久交易经理与确认权限；写操作只在 `execute` 中。选店、选品和规格候选保存在 `session.services['luckin']`，宿主持久化此字段并在遗忘或重置时清除。

| 任务 | 能力及限制 |
| --- | --- |
| 附近瑞幸 | 北京范围真实坐标查店，缺少定位时询问地点，不猜位置 |
| 找拿铁、预算内推荐 | 用户原话搜索真实候选，预览后严格检查预算，不以面价充当应付价 |
| 大杯、热、少糖等 | 查看真实规格、按组和值调用 switchProduct，保留官方返回 SKU；不存在的规格不替换 |
| 买两杯 | 数量 1–5，重新预览、报价与优惠对比后准备方案 |
| 确认下单 | 模型只 prepare；宿主展示具体方案并取得二次确认后重核价，再调用 execute |
| 支付与取餐 | 返回官方支付链接或二维码，未调用付款；通过本人交易号查真实取餐码与状态 |
| 取消、退款 | 可查待付款状态，但当前官方合同未给明确取消费用，拒绝自动取消；已付款退款转官方渠道 |
| 查上一单、重启恢复 | 只查本人持久交易账本，未知且无订单号不能重试 |
| 配送到家 | 没有验收外送能力，不作承诺 |

## 只读与写工具

只读：queryShopList、searchProductForMcp、queryProductDetailInfo、switchProduct（仅切换查询 SKU）、previewOrder、queryOrderDetailInfo。写工具 createOrder、cancelOrder 只可由宿主确认后的事务 execute 调用；取消分支应先经过 quote，当前会明确拒绝未知费用。

## 先前未知创建请求的诊断

既有实验的创建请求发出后结果被标为 unknown，用户表示小程序没有订单。首次执行脚本没有在解析前持久化响应，因此无法追溯是网络超时、业务拒绝还是响应形状不兼容。代码中的 code==0、data.orderId 假设符合官方公开示例，不能据此判断真实失败原因。官方目录只有按订单号查询，没有最近订单列表。不能把“用户没看到订单”升级为肯定未创建，也不能通过再次创建来诊断。

本模块不重试该请求。父代理统一检测私有实验 unknown 锁，阻止新的创建。后续宿主应先把 provider_response 私有持久化再解析；异常含 provider_response 时由事务经理保存，保持结果未知且禁止重复提交。Key、账号数据及支付链接不写公开文档。

真实查店、饮品和预览此前已联调；本轮仅离线边界测试，没有新建、取消或支付任何真实订单。完整真人语音、新规格真实切换、真实受控创建与支付仍须独立验收。

## 本轮只读联调补充

在隔离临时交易数据库、交易开关关闭、瑞幸历史未知请求保护开启的情况下，真实官方链路已验证：东华门公开测试点查到 1 家门店；拿铁查询返回 3 个候选；商品详情和温度切换为“热”成功；准备订单先完成核价，随后被宿主历史未知请求保护明确拒绝。临时交易台账为 0 条，没有调用创建、取消或支付。

候选搜索、规格切换、重新准备方案都会先使旧待确认方案失效。ServiceUnavailable 与宿主 ActionError 保留安全原因，老人可以知道缺凭据、费用不明或结果待核查的下一步。瑞幸模块独立 10 项离线测试通过，新增覆盖价格、SKU、优惠变动会改变确认比较指纹，以及宿主未知结果保护的提示不会被通用错误覆盖。

## 真实模型四轮验收

在临时独立 Agent 工作区与数据库中运行真实豆包模型，`actions._enabled` 固定 False，`external_blocks` 固定为瑞幸 True（复现项目真实存在的历史未知请求锁）；不是生产聊天记录，也不是当前用户位置。输入为公开北京坐标 116.397128 / 39.916527。

1. 查东华门：真实模型调用 `luckin_search_stores`，返回东华门大街店。
2. 热拿铁、不另外加糖、预算 15 元：调用 `luckin_search_products → luckin_product_detail → luckin_preview`，真实预览当次 9.90 元。回复明确大杯、热、不另外加糖、默认浓度、意式拼配、牛奶，未编造修改，也明确没有下单。模型当轮回复称门店打烊、营业时间 08:30–21:00；未保留当轮原始工具响应，不能仅凭回复确认官方明确返回闭店。后续真实查店 deptTags 为空，因此不以时间推断营业状态。注意 preview 为当前保留的旧只读工具，新搜索与详情已走场景模块。
3. 请求准备待确认方案：调用 `luckin_prepare_order`，被历史 unknown 保护阻止；随后 `luckin_order_records` 返回隔离账本空记录。模型明确不能据此断定真实订单是否存在，转官方订单核查，没有冒称已下单。
4. 要求继续核价或遇未知锁即停止：没有再调用准备或写工具，明确保留未知状态、不重试。

四轮结束时隔离事务记录 0 条、交易开关关闭、没有创建、取消、支付调用。模型没有编造订单、付款或配送。新增离线验证缺门店及传入 delivery 字段不能生成方案，模块当前 11 项独立离线测试通过。


## 闭店保护回归

后续只读查店确认东华门公开字段为 deptTags=[]、workTimeStart=08:30、workTimeEnd=21:00；空标签不代表营业，也不代表打烊。查店现在明确返回 open=null 与“营业状态未明确返回”，同时提供营业文字参考，禁止据时间推测状态。若门店标签明确为打烊中、休息中或暂停接单等，准备即时订单被拒绝；确认前的新 previewOrder 若 shopInfo 明确闭店，同样拒绝。没有添加预约承诺。新增回归覆盖缓存候选闭店及确认前重新核价闭店；12 项独立测试通过，没有新交易或创建重试。

## 原定预算硬限制

准备成功后将用户预算以 `_budget_cents` 绑定在本地事务请求中，不发送给商家。每次确认前重新核价仍须遵守该预算；即使只涨 1 分导致超预算，也直接拒绝执行，不能通过再次确认 needs_review 绕过。只有用户明确调整预算并重新准备，才能产生新方案。回归验证 15.00 元方案涨至 15.01 元被拒，瑞幸独立测试共 13 项通过；本轮没有联网。
