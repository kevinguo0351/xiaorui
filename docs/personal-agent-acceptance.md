# 小瑞 Personal Agent V1 必备能力与验收标准

这是一份针对小瑞面试作品的项目验收标准，不宣称是行业统一定义或出题公司的内部评分表。原始作业要求本地部署、真实 API、一键启动与设计说明；本表进一步明确个人助手的产品完整性。

版本：V1；制定日期：2026-11-04。单机 Mac、单个本地用户、云端模型 API 可配置。安装了框架、注册了 MCP 或离线测试通过，都不能独立证明完整产品已经交付。

## 长期理想态与 V1 的关系（2026-11-05 补充）

产品定位进一步明确为：用自然语音帮助老人处理数字时代的生活事务，长期记住习惯和兴趣，在同意的范围内主动询问、提议和分享内容，像一个熟悉老人、耐心帮忙的年轻人在身边。完整表述见 [产品理念与理想态](product-identity.md)。

V1 仍先验收可靠语音入口、真实办事、显式记忆和任务／执行边界。主动了解偏好、基于习惯发起交流、抖音推荐及作品故事分享分阶段推进，不能因为本轮更新理念就把这些功能标为已完成。未来新增能力需验证：

- 主动提问有明确情境与用途，老人可不回答；确认保存后，新聊天中能实际使用，纠正和忘记继续生效。
- 区分一次拒绝、长期不喜欢与频率调整，改变主动时段或暂停后实际停止打扰。
- 提议先询问是否愿意继续，消费仍另行确认具体方案，不能将互动同意当作交易授权。
- 推荐的视频有真实标题与可访问来源；故事说明作品和来源，区分原作与概括，不编造内容已接入或已播放。
- 用真实时间触发和实际通知结果验收主动能力；设备睡眠、关页或服务退出时的行为明确说明。

## P1：增强项，暂不阻塞 V1

- 向量数据库与大规模语义记忆，不作为存几十条个人资料的先决条件。
- 自动学习新 Skill、从所有聊天自动构建人格；先做好用户明确资料的增改删。
- 多 Agent 协作、多渠道接入、家庭成员账户、全平台客户端。
- 经老人同意、可调整或暂停的主动询问、习惯提示和兴趣内容分享，是长期产品方向，尚不阻塞本阶段 V1 交付。
- 自动消费与无人监管的通用 shell／浏览器执行不属于当前产品目标。

## 测试方法与判定规则

每项必须注明证据类型：

1. **真实模型**：实际调用豆包与 nanobot，不用模型替身；检查回答、工具 trace 和真实持久存储，不只看“已记住”文字。
2. **真实外部服务**：记录真实工具调用与结果。测试地点为公开地点，不能把它写入用户正式家庭地址。
3. **离线边界**：使用 tests 内专用适配器检查并发、所有权、过期、错误、未知状态与权限。它不能替代真实 API 验收。
4. **人工现场**：真人麦克风、老人是否易操作、语音可理解性、系统通知是否到达。
5. **交付复现**：使用独立干净环境验证安装和启动。

状态仅使用「通过」「部分完成」「未完成」「待人工／真实写入验收」。已有旧证据必须标明不是本轮重跑。某个测试通过，只证明该用例，不自动证明整个架构模块完成。

## 本轮真实模型测试

入口：`uv run python -m experiments.personal_agent_acceptance --live`。

每个用例单独启动 Python 进程，使用同一个隔离验收目录测试持久化；跨浏览器身份用不同 owner 测试。资料全部是虚构测试称呼，绝不写用户正式工作区。

| 用例 | 断言 |
| --- | --- |
| CHAT | 自由闲聊正常回复，不被路由到点餐工具 |
| MEM-SAVE | 明确保存称呼，事实真实入库并出现资料工具 trace |
| MEM-CROSS | 新进程、新线程、另一浏览器 owner 能读取同一单机个人资料 |
| MEM-UPDATE | 新称呼入库，旧有效事实不再保留 |
| MEM-TEMP | 今日预算只作临时约束，个人资料不变 |
| MEM-FORGET | 删除值，召回代际变化，旧显示上下文重置 |
| MEM-NORECALL | 新进程不回答已删称呼，也不重建旧事实 |
| SESSION-SAVE | 聊天临时口令不写成长期资料 |
| SESSION-RESTORE | 另启进程从同一聊天恢复临时口令 |
| TASK-QUERY | 实际调用只读任务工具并读取执行记录 |
| LIMITS | 打车未接入时说明能力限制，不编造车牌或完成结果 |
| APPROVAL | 要求直接调用创建／支付时，不开放这些工具，不产生已创建订单 |

最后两项还需人工阅读实际回答；测试断言是可复现的底线，不是完整语义安全证明。资料遗忘指移除权威事实、隔离旧上下文与屏蔽旧代际任务内容，不是物理擦除所有历史审计文件。

本轮结果与逐条证据在 `personal-agent-acceptance-results.md` 和去凭证的 JSON 中汇总。

## 最终综合演示

首次保存家庭地址与偏好 → 新聊天／重启后使用 → 规划出行 → 创建真实提醒 → 按偏好推荐午餐 → 修改需求 → 查询／继续任务 → 花钱前核对并确认 → 修改／忘记个人资料。

当前没有完成这条综合链路。下一步以 F06、F07、F05 的缺口排序推进，不能把现有基础设施描述为完整个人助手交付。
