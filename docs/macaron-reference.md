# Macaron 产品参考

调研日期：2026-11-04。这里指 Mind Lab 的 macaron.im 生活型 Personal Agent，区分其他同名产品。证据来自官方产品页、FAQ、相关论文及官方 GitHub；没有登录实测商业 App，也没有验证其第三方账号交易能力。

## 可确认的公开方向

- [官网](https://macaron.im/) 将个人化记忆、陪伴和生活工具生成作为主要产品表达。
- [官方 FAQ](https://macaron.im/qa) 描述偏好／经历记忆、语音、按自然语言需求创建个人项目，以及项目卡片、项目管理、构建进度、失败重试／取消和完成通知。
- 项目示例包括运动记录、旅行日记、个性化饮食记录。生成这些工具不自动证明能够在外部平台完成购物、叫车、挂号或支付。
- [Macaron-A2UI 论文](https://arxiv.org/abs/2605.24830) 将界面用于信息收集、偏好调整、确认和多目标组织，说明其产品方向不限于纯文字回答。

## 找到的开源资料

1. [macaron-artifacts](https://github.com/MindLab-Research/macaron-artifacts)：官方开源的 UI4A 社区实现，Apache-2.0。README 描述本地 WebUI、流式可交互界面、跨轮持久 Canvas，以及与多种 Agent harness 的适配。它不是商业 Macaron App 的全部源码。当前列出的 harness 包括 Claude Code、Codex、OpenCode、pi、Hermes、OpenClaw，不能据此推定 nanobot 已有现成适配。
2. [Macaron-V1](https://github.com/MindLab-Research/Macaron-V1)：模型与运行框架研究入口，链接到模型权重、技术报告和其他仓库。模型开放不等于商业产品、Deep Memory 系统和所有服务集成都已完整开源。此项目公开参考部署面向 GPU 服务环境，不作为本次 Mac Air 本地应用的模型替换方案。
3. [hcp-sdk](https://github.com/MindLab-Research/hcp-sdk)：README 明确当前是包装模式的 Python 控制层，依赖 pi-hcp／pi-acp 链路，自身不独立实现完整 Agent。不能当作无需额外运行时的 Python 替代库。

## 对“小瑞”的启发（我们的产品判断）

| 参考方向 | 小瑞可采用的方式 |
| --- | --- |
| 持续了解同一个人 | 在已实现的可增改删个人资料上，逐步加入跨任务使用，而不只保存聊天 |
| 对话产出可长期使用的生活工具 | 用受控组件构建买菜清单、任务卡、记录表；数据真实持久化，可在后续聊天继续用 |
| 界面参与办事过程 | 用地点选择、时间选择、方案比较和确认卡片降低老人输入负担；首页仍保持简洁 |
| 工具与任务有生命周期 | 创建后能查看、修改、继续、取消，并报告实际结果，而不是一轮文字回复就结束 |
| 自然陪伴与语音 | 记住称呼和表达偏好，用短句、清楚的中文解释当前状态 |

当前固定套餐卡片是受控的结果渲染，不等于通用 Generative UI。更通用的表单／列表／任务卡需要独立设计数据与动作协议。

## 对现有技术路线的影响

保持 nanobot 底座与已验证的真实 API／交易确认层，先参考 Macaron 的产品闭环和交互契约；不因为发现新项目就立即再次替换整套运行时。若未来采用 UI4A，需要单独验证 nanobot 事件适配、权限、状态持久化、依赖成本和适老交互。

小瑞仍要按原始任务验证真实外部 API；生成一张购餐卡片、一个记账表或一个提醒界面，都不能替代实际核价、执行或通知。

公开资料没有给出可据以确认的全部第三方连接器及权限目录，因此本报告不声称 Macaron 已打通淘宝、滴滴、高德、医院挂号等具体服务。
