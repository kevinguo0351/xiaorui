## V1 通过标准

| 项目 | 必须观察到的结果 | 当前缺口 |
| --- | --- | --- |
| 真实 Agent | 自由描述、追问、选择工具、返回可核实结果，未接入时直说 | 更多真实跨场景用例 |
| 稳定身份与记忆 | 新聊天／重启使用已保存资料；可查看、更新、忘记；临时条件不自动永久化 | 历史检索与资料管理体验；兴趣习惯的主动了解未实现 |
| 持久会话 | 同一聊天重启可继续，其他线程临时条件不混入，记录可查询 | 完整历史检索体验 |
| 持续目标 | 一个目标有独立 ID，待补充后继续，可修改／取消；重启呈现可信状态 | 当前主要是每轮执行回执与交易方案 |
| 跨场景 | 相同入口和个人资料完成出行、用餐等不同领域任务 | 完整跨场景真人演示 |
| 确认与执行 | 具体方案确认后一次执行，变化重新确认，未知不重试；型号／地址／金额均可核对 | 真实订单、支付与叫车逐项现场验收 |
| 语音与适老交互 | 连续两轮、插话、改口、通话中打字、字幕与播报一致，错误后可恢复，挂断释放麦克风 | 真人与老人现场验收、方言、回声和时延 |
| 真实提醒 | 创建／查询／修改／取消并到时收到通知，睡眠与退出行为明确 | 用户调度、苹果提醒事项和通知尚未接通 |
| 交付复现 | 干净下载、填凭据、一键启动，文档与实际一致 | 干净环境最终验证与综合演示 |

先通过这些行为，再扩展主动了解偏好、频率与安静时段、内容来源、分享反馈和暂停。它们属于长期产品方向，不因写入文档就算上线；自动消费不属于当前目标。

## 验证方法与命令

离线边界使用 `tests/` 内专用替身；真实模型和真实服务分别记录实际工具轨迹；真人麦克风、通知送达和老人体验现场观察；交付另用干净环境验证。

```sh
uv run python -m unittest discover -s tests -q
node --test frontend/tests/voice.test.cjs
npm --prefix frontend run build
```

以下命令会调用真实云端接口并可能产生费用，只在隔离目录使用测试资料：

```sh
uv run python -m experiments.personal_agent_acceptance --live
uv run python -m experiments.speech_live_probe --live --audio
uv run python -m experiments.contact_voice_probe --voice-only
uv run python -m experiments.contact_live_probe
```

真实消费必须先审阅并明确确认具体方案，不能把运行实验命令当作授权。旧探针的某项断言只适用于其标注版本与范围，失败要核查实际原因，不能自动重试交易。

`docs/acceptance/` 的 JSON、`docs/research/` 的原始快照和 `experiments/` 的脚本保留用于追溯。原始账号数据、家庭地址、订单号与支付链接不放公开证据。资料“忘记”移除有效事实并隔离旧召回，不表示审计文件被物理擦除。
