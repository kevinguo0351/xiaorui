# 北京麦当劳老人任务场景

本模块是 `app/mcd_scenario.py`，通过共享事务管理器准备、确认前重核价和执行；不注册任何模型直发订单或取消工具。沿用 `McdService._connection` 的工具发现与真实 JSON Schema 校验，无 mock 数据回退。隔离测试与真实只读查询分开记录，没有在本轮开发中创建、取消或支付真实订单。

## 最新外送开发与广州只读验收（2026-11-04）

用户明确要求用广州已有地址试验，因此外送地址工具增加显式 `city=广州`；默认仍为北京，不因北京没有候选自动换城。地址按行政城市识别，广州市北京路不能被当成北京市。官方地址查询无分页／城市输入，本次返回 10 个广州地址；用户确认与 App 为同一账号，差异原因尚未确认，不能据此认定 App 没有北京地址。

通过 `experiments/mcd_delivery_acceptance.py` 调用实际场景模块和官方接口：

- 广州已有地址 → 3 家可配送门店，其中 1 家营业 → 麦香鱼菜单 3 个候选 → 单品详情 → 不需要餐具 → 含费核价 → 执行关闭的本地方案，通过。
- 当次测试：麦当劳广州市南路得来速餐厅，麦香鱼单品 1 个，麦乐送，总价 **31.10 元**；官方配送费 **6.00 元**、打包费 **1.10 元**。这只是报价快照，没有下单，不代表用户家庭地址或北京配送能力。
- 本次真实方案重新查配送资格和核价通过，比较一致，仍为 31.10 元。确认前重新查所选地址的配送门店，业务编码匹配且非闭店才继续核价；地址不再覆盖、门店关闭、超预算会停止。价格／费用变化需重新确认。
- 页面和语音方案展示官方费用分项、餐具和备注；未返回费用不当零，不保证商家接受备注。订单查询提取官方预计送达时间与配送员称呼，去除手机号和完整收件资料；前台展示与播报需真实订单后再验收。
- 完整真实模型对话被豆包 `SetLimitExceeded` 用量上限阻止，未宣称通过真人语音或交易验收。另修复本地 32k 上下文预算不足的问题，默认改为可配置 64k；配置不能超过所用模型支持长度。

复现：`.venv/bin/python -m experiments.mcd_delivery_acceptance --city 广州 --address-index 1 --store-index 1 --keyword 麦香鱼 --product-index 1 --tableware no`。序号仅对当前返回结果有效；先不传商品／门店序号可分阶段查看私有报告，不能盲用历史序号。脚本只允许固定只读工具，拒绝创建订单；详细地址与方案凭据仅保存在忽略的 `.local-data/mcd-delivery-development/`，不要推送 GitHub。

官方确有 `delivery-create-address`，本项目尚未开放该写工具。此前“官方没有新增地址工具”的说法已纠正，见[官方工具目录](https://github.com/M-China/mcd-mcp-server)。

## 任务矩阵

| 老人任务 | 实现路径／当前边界 |
| --- | --- |
| 附近买麦当劳、公司附近吃午饭 | 北京关键词搜门店，用户选店；自动定位由宿主另行提供 |
| 午饭送到家 | 查本人已有地址，确认北京地址，查可配送门店；无地址请家人配置 |
| 看菜单、找指定餐品 | 当前门店菜单与名称筛选，不编造可售商品 |
| 套餐含什么、换套餐内容 | 真实详情 rounds；每轮只支持单选，由用户逐项选择 |
| 预算、数量、堂食／外带 | 数量 1–5；取餐方式来自官方核价返回，不能默认代选；超预算由对话重新选择 |
| 配送费、是否要餐具、备注 | 外送明确餐具选择，备注最多 50 字；总额来自官方核价，未返回费用分项不当零 |
| 少辣、过敏、糖尿病等 | 不根据商品名称保证安全；特制改配与医疗建议未实现，明确说明 |
| 确认下单、反悔、更改地址 | prepare 返回具体方案；宿主绑定本人和版本进行二次确认；变化重核价重确认 |
| 付款、什么时候能吃 | 返回官方支付入口；按真实订单状态回答，不能把订单创建当支付或配送成功 |
| 看我的订单、取餐码 | 只查询共享事务台账中本人已创建订单，返回精简状态／取餐码 |
| 取消订单 | 必须官方明确可取消和取消费才准备确认；当前常见 query-order 没有这些字段时明确不自动取消 |
| 网络断开、重复说确认 | 宿主事务台账防重，未知结果不重发；先核实官方订单 |
| 已付款后修改或退款 | 未提供可验证合同，不承诺自动退款，转官方渠道 |

## 接口契约

`McdScenario(transactions, provider=None)` 提供 `.schemas`、`dispatch(session, owner, name, arguments, events)`、`quote(action, request)`、`execute(action, request)` 和 `query_order(order_id)`。

- session.services.mcd 保存当前地址标识、门店、菜单候选；候选序号不能从其他会话传入。地址查询去除电话和收件人。
- prepare 使用共享 `transactions.prepare(owner, provider='mcd', action=..., request=..., quote=...)`，事件为 action_plan。公共 plan 的确认凭据由宿主从模型输出中去除。
- quote 返回稳定 comparison，覆盖原始门店编码、商品／数量／套餐、地址 ID、履约方式、总额及实际返回费用。确认重核价改变任一项，宿主重新确认。
- execute 仅由共享事务经理调用；create 使用官方 create-order，返回 order_id 和 payment_url。取消返回取消请求结果后仍需 query-order 核实最终状态。
- query_order 不返回手机号和完整配送地址，只返回状态、金额、取餐码等必要信息。

所用远程只读工具：query-nearby-stores、delivery-query-addresses、delivery-query-stores、query-meals、query-meal-detail、calculate-price、query-order。受控写：create-order、cancel-order。

## 验证

`.venv/bin/python -m unittest discover -s tests -p 'test_mcd_scenario.py' -q`：15 项通过。覆盖本人配送地址与隐私、明确取餐方式才能提案、配送参数／含费总额一致、费用单位、默认城市与显式广州、行政城市和路名区分、确认前配送资格失效、商品详情不一致、送达时间提取，以及其他商家订单拒绝与未知取消费拒绝。

真实联调仍需在用户选定北京地址和商品后逐步验证；已有历史麦香鱼待支付测试订单不受本模块测试影响。官方返回地址列表若不是当前支持的列表容器会明确报错，不能以模板数据替代。

本轮真实只读结果：官方地址响应为 dict.addresses（10 条），地址字段为 addressId/contactName/fullAddress/phone，适配已覆盖 fullAddress 并不保存电话及联系人；北京王府井门店搜索返回 5 家。后续菜单请求工具失败，具体原因未诊断，因此本轮没有声称外送菜单／配送核价已联调通过。


## 整合后的真实模型聊天验收

临时 AgentService 工作区、actions._enabled=False，并将所有 scenario.execute 和 McdService.create_order 替换为拒绝执行函数。没有读写生产会话、没有创建/取消/支付。

1. 北京王府井查店：真实 mcd_search_pickup 完成，返回 5 家门店，模型指出官方营业字段显示未营业。
2. 选第 1 家、麦香鱼 1 个外带：mcd_menu 两次工具错误。模型说明无法取得本轮真实菜单，不生成虚构报价。
3. 再明确单品外带：模型没有继续盲目调用，说明缺有效候选，未准备方案。
4. 说“确认下单”：host.confirmation 拒绝，没有对应待确认方案；最终 actions=[]。

这轮没有拿到含费方案，因此不能称准备或交易验收通过。闭店门店不应准备可提交方案，已增加 open/businessStatus 明确为 False 的硬拒绝与回归测试。需确认营业状态和接口返回后才能继续真实菜单/外送报价验收。


### 最后只读补测：营业中的北京站周边门店

仅搜索北京站一个地标，返回 5 家门店，2 家官方 open=True；选择麦当劳北京崇外新世界餐厅。新 McdScenario 的菜单筛选麦香鱼、单品详情、第一次 prepare 返回官方取餐方式、明确选外带后第二次 prepare 全部成功，生成临时本地 disabled ActionManager 的待确认方案。

本次快照：麦香鱼单品 1 个，外带／店外取餐柜，总额 23.00 元。官方未返回费用分项（fees={}），不能将缺少的分项视为零。没有创建任何真实订单，没有付款，没有取消。此结果只证明到店外带准备链路通过，不代表外送或真实交易验收通过。mcd_menu 现同样在门店明确未营业时直接解释并拒绝远程菜单查询。

明确预算使用严格整数 budget_cents（分），仅保存在本地request顶层，不发给商家。准备和确认前重核价均校验最终含费总额，超预算即拒绝，不能通过重新确认自动越预算；必须用户明确修改预算后准备新方案。新增回归同时覆盖准备超预算与重核价超预算。
