# 语音聊天与复合回复设计

用户于 2026-11-04 确认：用极简聊天主体替代原来的任务侧栏与独立任务页面。

## 入口与对话

初始页突出问候和语音入口，设置、历史入口弱化。开始对话后显示大字聊天记录，输入固定在底部；助手的问题、答复、餐厅、餐品与最终方案都位于同一条对话流。老人可通过说话完成选择，也可点击卡片。

当前先做文本可操作原型。语音未接入前明确标注，不能把录音按钮或浏览器合成声音当作豆包接口已完成。文本原型也不代表已接入 nanobot 自主规划。

## 套餐卡片

展示至多三个真实可行方案，用 A/B/C 标识。每张包含官方图片、名称、实际组合和核价金额。少于三个就展示实际数量，无可行方案明确解释；不补造图片、价格或菜品。

卡片价格必须经过真实组合核价。菜单起售价只能用于候选筛选，不当作成交总价。外送阶段还要包含配送费，并确认地址；当前只有自取接口时明确说明，不能答应送到家。

## 复合回复

同一次回复包含结构化卡片与简短 speech_text，后续由豆包 TTS 朗读。播报按 A/B/C 简介和一个有依据的推荐理由，不逐条念参数。默认选项不意味着已满足不辣、去冰等偏好，没有官方信息或实际特制参数支持就要澄清。

## 选择与确认

“我要 B”只代表选择方案。选定后再次核价，生成最终确认卡片，展示门店／地址、商品组成、费用和总价，再明确确认下单。方案变更或过期后旧确认失效。

聊天记录中的旧卡片不应授权旧订单。超时或未知结果时先核查，禁止自动重新下单。当前开发阶段真实订单默认关闭，不能用模拟成功界面代替。
