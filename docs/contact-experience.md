# 联系人式交流：需求、实现与验收

确认日期：2026-11-04。本对话的持续实施目标是让小瑞像一个聊天联系人：可以连续发文字，也可以接通语音通话；两种输入共享会话、个人资料和生活任务。

## 最新输入区决定：沿用微信手机端的入口逻辑

用户进一步确认：保留此前的文字／语音输入切换，持续通话放到加号展开菜单中，不用通话按钮替代语音输入。

- 左侧图标在文字输入与单条语音输入间切换。语音输入沿用适老的点击开始、再次点击停止并发送；切换回文字会取消未发录音。
- 右侧加号展开“图片”“语音通话”。展开、切换输入本身不请求麦克风；只有主动录音或拨通时请求。
- 图片支持选择、待发预览、移除、附文字发送及历史恢复。每条最多四张，源文件支持 JPG／PNG／WebP、每张最多 8 MB。后端解码、限制像素并重新编码，移除原始文件名和 EXIF；图片按浏览器会话隔离保存在本机。
- 发送后，图片通过 nanobot 的 media 参数交给当前豆包模型；上传成功不等于模型识图通过。图片中的文字不是交易授权，带图消息也不能触发宿主确认执行。
- 加号中的语音通话仍保留持续收音、实时字幕、插话与挂断；通话中可以打字。

本轮 130 项 Python 测试、5 项前端录音／通话测试及生产构建通过。图片所有权、非法图像、模型输入路径传递、带图不能确认交易和单条录音切换取消均有测试。真实看图仍待模型可用后验收；真人录音、回声与听感仍待现场测试。

浏览器已实测文字／语音切换、加号展开、测试图片选择与预览、图片附文字发送和“已送达”状态；没有执行生活业务。真实看图请求仍返回模型用量上限提示。输入区预览见 [截图](wechat-composer-preview.png)。

## 验收目标

1. 小瑞思考或查询时，输入框和发送按钮仍可使用。每条消息立即显示送达状态，不以整轮模型回复作为接收条件。
2. 连续短句按顺序保存并理解，补充条件和改口参与同一任务；旧结果不能覆盖更新后的需求。
3. 一次点击接通后持续收音，实时显示当前识别文字，停顿后自动提交；不用每句话重新点击录音。
4. 小瑞播报时仍可插话，插话停止待播音频；通话中可以同时打字，挂断后停止麦克风和播报。
5. 文本、语音使用同一会话与工具权限。真实消费仍绑定具体方案确认；停止播报、挂断、网络中断不代表远端订单被取消。
6. 刷新可以恢复已接收消息和结果；重启将未结束的消息标为中断，不自动重放可能产生写操作的输入。

## 已实现

- `app/contact.py` 提供 SQLite 消息收件箱、客户端消息 ID 去重、单会话串行执行和独立于请求连接的后台处理。350 毫秒内连续短句可以合并，确认口令单独处理。
- `/api/contact/messages` 先返回接收结果；`/api/contact/events` 通过 SSE 推送送达、开始、模型文字增量、进度、完成和失败。连接断开不重发任务，重连按事件游标补收。
- 有补充消息排队时抑制旧一轮的后续增量和最终展示，然后使用同一持久模型会话处理补充。已开始的模型请求会完成到安全边界；没有强行撤销已提交的外部写操作。
- 确认在消息到达时绑定方案 ID 和版本；条件改变使旧方案失效。等待执行的口令不能批准随后生成的另一份方案。
- 前端输入不随模型处理锁定，展示流式文字和送达状态，文字输入与通话条并存。
- `useVoice.ts` 保持一个麦克风流，按语音活动开启现有豆包 ASR 连接，展示 partial 字幕；每轮结束后自动接续，保留连接切换时的有限音频缓冲。
- 当前接话采用音量活动检测与约 1.8 秒停顿；约 120 毫秒连续语音活动会停止播报。开启浏览器回声消除与降噪。
- 回复按短句逐段请求现有豆包 TTS 并播放；打断会取消合成请求并停止本地播放。当前仍在完整模型回复确认后开始自动播报，不声称端到端语音模型或音频字节级流式播放。
- 明确识别豆包 `SetLimitExceeded`，只显示可理解的额度提示，不把服务暂停当作网络故障或执行成功。

## 验证与当前阻塞

后端收件箱测试覆盖即时接收、合并、处理中补充、旧回复失效、去重、会话隔离、重启不重放和遗忘后不回放旧资料。另有真实执行层测试确认口令不能批准另一份方案。

本轮全量 Python 离线测试 120 项通过，前端通话生命周期测试 3 项通过，TypeScript 与生产构建通过。测试不产生真实订单或叫车。

前端通话生命周期测试使用测试专用音频、WebSocket 和浏览器对象，覆盖连续两轮、播报期间保持收音、插话停止音频和挂断后不提交转录。这些测试不访问真实麦克风，不能代替真人验收。

真实浏览器已观察到处理中继续发送、两条消息分别显示已送达。真实模型调用返回 `SetLimitExceeded`：账号模型用量上限使服务暂停，因此本轮不能判定真实连续理解或完整通话已经通过。需要账号恢复可用后复测。

### 充值后的复查

用户告知完成充值后，通过新建隔离 HTTP 会话与真实 SSE 再测：三条输入可接收，文本模型仍返回 `SetLimitExceeded`，因此连续理解尚未通过。官方文档将该错误归于模型用量上限或安心体验模式，需在开通管理核对，不能将账户余额充值视为模型已恢复的证据。

独立的真实 TTS → ASR 两轮检查已通过，分别得到 14 次、9 次实时 partial 和正确 final 转录；使用生成的测试音频，没有录制真人麦克风，没有查询业务或执行交易。证据见 [语音复测 JSON](acceptance/contact-voice-live-2026-11-04.json) 与 [充值后复查摘要](acceptance/contact-recharge-recheck-2026-11-04.json)。真人接话与回声仍待验收。

复现脚本：`python -m experiments.contact_live_probe` 验证真实消息接收、改口、SSE 与后续上下文；`python -m experiments.contact_voice_probe --voice-only` 只验证真实语音合成与识别，不调用文本模型。去掉 `--voice-only` 时再验完整音频到回复链路。

官方参考：[安心体验模式及 SetLimitExceeded 说明](https://docs.volcengine.com/docs/ark/free-tokens-only-mode?lang=zh)。若选择关闭安心体验模式，官方说明关闭后无法重新开启，超出免费额度按实际 Token 计费；本轮没有修改账号设置。

仍待验证：真人正常音量、长停顿、方言、扬声器回声、连续插话、首次播放权限、断网与重连、实际回复时延。固定停顿检测不能等同于语义判断老人是否说完；若抢话或漏话明显，再评估 Silero VAD、Pipecat turn detection 或独立实时语音模型。当前沿用已接入模型，不更改账号额度设置。
