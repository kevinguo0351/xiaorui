# Personal Agent 底座整合

本阶段先整合运行底座，不增加地图、提醒事项、外送等具体生活业务。已有麦当劳能力作为回归用例保留。

## 分层

- **运行时**：固定 `nanobot-ai==0.4.0`，使用其 `AgentLoop` 与 `Nanobot` SDK 运行模型工具循环及持久会话。小瑞负责宿主配置、事件卡片和权限边界。
- **个人工作区**：单机稳定个人身份与浏览器聊天线程分离。新对话更换线程，不删除已保存个人资料。
- **权威资料与任务记录**：本地 SQLite 保存资料版本、删除标记、可恢复的展示上下文与任务执行状态。资料由明确工具操作修改，不声称已实现后台自动人格建模。
- **受控 Skill**：明确注册核心个人资料能力与现有用餐能力。目录中的 `SKILL.md` 说明能力与规则，执行仍由经过校验的工具提供；不是任意社区 Skill 的自动安装器。
- **调度宿主**：`FoundationScheduler` 使用真实 nanobot `CronService`，接入宿主 start/stop 生命周期。默认零任务，不调用模型、不创建提醒、不发送通知、不交易。用户调度与通知交付尚未接入。

## 工具与命令边界

仅传入空工具表不够：nanobot 的 `AgentLoop` 初始化时仍会发现并加载默认工具。宿主必须关闭 file、exec、web、cli_apps、my 和 image_generation，并使用自有工具注册表作为最终白名单，拒绝未明确注册的工具。初始化完成后应断言有效工具名精确匹配预期。

`Nanobot(AgentLoop.from_config(config, tool_registry=registry), config=config)` 是当前固定版本的组合方式，不通过 `bot._loop` 修改运行中的内部状态。必须同时清空默认命令路由，避免 `/dream`、`/restart` 等命令绕过小瑞的宿主能力定义。原始 MCP 下单工具、shell、任意文件读取和自动子 Agent 不对模型开放。

订单确认仍位于原有服务端执行层，绑定具体方案、金额、版本、所有权与有效期。工具说明、模型承诺和 Hook 抛异常不能取代交易授权。

## 持久化与恢复的含义

运行时会话负责模型上下文；宿主记录负责网页展示和当前候选，两者必须使用一致的线程标识。资料遗忘后需要轮换旧会话的召回边界，避免旧上下文重新提供已删除事实。

任务恢复先保存并展示可信状态。服务启动时遇到执行中的任务，应记为 interrupted，不能把重放未知外部写操作当成恢复成功。已有交易状态机继续将不确定订单记为 unknown。

调度宿主只接受固定的一次性内部 maintenance 事件，使用持久执行认领避免重复；失败或中断后不自动重放。Mac 睡眠、应用退出时不保证触发或通知送达，因此这里不能称为已完成用户提醒功能。

## 验证边界

无网络源码构造验证已通过：关闭默认能力、自有过滤注册表、空命令路由后，可以正常构造和关闭 nanobot，且有效工具与命令均为空。调度测试覆盖空任务 start/stop、重启恢复、失败不重放及任意 agent_turn 拒绝。

实际运行时工具调用、跨进程个人资料和当前网页接入验收由根代理补充。正式测试只在临时目录使用测试配置，不读取或修改用户 `~/.nanobot`。

## 尚未完成

地图、苹果提醒事项、用户可创建的定时自动化、通知交付、自动经验学习、完整长期任务编排仍属于后续阶段。已有底座模块和现有业务的接入结果应逐项验收，不能因为安装了框架就将上游全部功能视为小瑞已支持。

## 离线验收结果

本轮全量 55 项测试通过。新增宿主测试实际构造 nanobot（没有模型网络请求），检查有效工具集合精确匹配 Skill 白名单，默认命令路由为空；同时验证临时数据库重开后的历史与候选恢复、浏览器 owner 隔离、非法工具拒绝、确认凭证不进入模型结果、失败任务保存以及新线程保留个人资料。调度宿主新增 3 项测试通过。
