# 原版聊天与语音增量验收

本轮在 `trial/local-run-rust-assessment` 改进 React 版，保留微信式输入、消息、图片和语音通话。Flutter 分支未加入本轮改动。

## 已实现与实测范围

- 状态条固定在输入区旁，使用真实录音／识别／工具调用／回复整理／播放状态；没有虚构百分比。
- 查询进度细化为实际工具对应的麦当劳菜单、瑞幸饮品、滴滴地点或车型等；准备方案明确尚未下单、叫车或取消。
- 单条语音结束时立即释放麦克风，等待最终识别期间仍可取消；切到文字或打开更多功能会丢弃未提交转录。
- 连续通话保留麦克风，初始静默阈值为 3 秒（设计估计，非真人最佳值）；“我说完了”立即结束本句，挂断停止收音和声音。
- 当前句播放时预取下一句，最多提前一句；停止／插话／挂断会中止预取，迟到音频和旧回复不自动播放。
- 后端 trace 分别记录工具、首段文字、包含工具的运行总时长、播报改写时长；前端提供每句 TTS 接收及播放时点诊断，不记录正文或凭据。
- 非展示查询回执不生成额外空白气泡。缺配置提示使用容易理解的中文，具体配置项保留在开发文档。

## 停止边界

当前有停止播报、取消未提交录音、通话挂断和“我说完了”；没有通用的后台任务终止按钮。已接收消息仍可能继续处理；停播或挂断不能当作取消订单、叫车或付款。实际订单取消仍按已有受控方案执行。

## 接口检查

已执行 `uv run python experiments/read_only_service_check.py`。麦当劳、瑞幸、滴滴均为 `not_configured`，未发远程查询。记录见 [安全接口矩阵](react-service-check.json)。检查器只允许固定的公开门店／地点查询，分别报告目录发现与业务查询结果，不输出原始响应和凭据。

本机需要分别在 `.env` 配置 `ARK_API_KEY` / `ARK_MODEL`、`DOUBAO_SPEECH_API_KEY`、`MCD_MCP_TOKEN`、`LUCKIN_MCP_TOKEN`、`DIDI_MCP_KEY`。历史其他环境成功的证据不能证明当前机器已连通。密钥不要发到聊天或提交 Git。

## 流式能力与下一步

目前为实时识别与字幕、SSE 文字、逐句完整 MP3 播放加一句预取；仍然等待正文与播报稿完成，尚非音频字节流播放或端到端语音模型。未测得本轮真实耗时，因此没有声称降低了多少秒。

官方已有 [双向流式 TTS](https://docs.volcengine.com/docs/doubao-voice/websocket-bidirectional-streaming-v3?lang=en) 与 [端到端实时语音](https://docs.volcengine.com/docs/doubao-voice/end-to-endreal-time-speech-large-model-api-access-document?lang=en) 接口。这是后续可验证的接入方向，不是本轮已完成能力。先补凭据记录各段耗时、验证连续两轮／回声／长停顿，再决定是否升级；升级仍须保留现有宿主交易确认与屏幕文字一致性。
