## 明确保留待验收

本机 `.env` 与进程环境均未提供必要的 `ARK_API_KEY`／模型、`DOUBAO_SPEECH_API_KEY`、`MCD_MCP_TOKEN`。健康检查与界面显示未配置，不输出凭据。

- 真人麦克风权限拒绝、空录音、录音字幕、点击／按住录音、取消、连续两轮、重录打断：实现已加入，部分竞态离线测试通过，真实浏览器录音待验收。
- 豆包 ASR → Agent → 麦当劳真实门店／菜单 → 豆包 TTS：待配置并开通权限，不能算闭环完成。
- 供应商超时、网络中断后的完整恢复、浏览器拒绝播放后的手动重播、实际慢速听感：待真实环境验证。浏览器 offline 开关未可靠中断既有 SSE，本轮不将其记为断网通过。
- 刷新查询进行中的页面：已恢复接收事件与最终结果；后端既有快照不保存 started/progress，完成前可能显示“已收到”，不会伪造执行进度。
- Android APK、iPhone、真实下单／取消／付款、买药买菜、后台监听和主动提醒：不在本轮范围。

## 实施调整

计划中的“服务端新增语速档位”未落地：缺少语音凭据，无法按计划验证新增供应商参数。沿用原服务端 `speech_rate=-10`，通过 just_audio 的本地播放速度提供慢速／正常；这不代表远端语速参数已验证。

复核发现麦当劳 scenario 查询原先没有结果事件，任务可能误标为需要补充。现已添加 `query_result`，携带工具、成功／失败、结果与官方服务来源；对应后端与客户端状态测试覆盖此缺口。
