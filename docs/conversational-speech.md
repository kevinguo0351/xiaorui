# 小瑞的自然播报设计

2026-11-05。用户确认的方向：像成年人之间自然交谈，理解当前任务与上下文，挑重点帮助老人决定下一步；不逐字朗读屏幕文本，不哄小孩。

## 信息如何分工

屏幕保留完整选项、价格和具体方案，`text` 用于阅读；独立的 `speech_text` 用于听。TTS 只负责把已经设计好的口语说出来，不负责决定说什么。

处理链路：真实工具与任务状态 → 当前阶段判断 → 语音重点选择 → 口语组织 → 事实检查 → 豆包语音合成。`app/speech.py` 实现这些步骤，接入 `AgentService` 的正式回复与持久历史。

阶段策略：

| 场景 | 播报方式 |
| --- | --- |
| 看车型 | 说明车型和预估费用已在卡片中，引导用户选择；默认不报完整价格表 |
| 已有预算 | 从本轮真实候选中选择一两项预算相关重点，其他选项概括处理；不替用户选车 |
| 看不清／请念出来 | 展开说出当前可见候选及费用，明确是预估或尚需核价 |
| 改口只看看 | 承接最新要求，保持浏览阶段，不继续催确认或消费 |
| 缺少信息 | 围绕当前问题追问必要信息，不反复问已经说过的条件 |
| 花钱前确认 | 由宿主事实组织，保留具体地点、商品／车型、规格、金额、实际执行提醒与确认方式 |
| 结果未知 | 明确还未核实，提醒不要重复提交，不说成失败或成功 |
| 司机／订单进度 | 根据真实状态播报；有车牌才说车牌，没有预计时间就不猜 |

## 实现选择

沿用现有豆包模型与 TTS，没有引入另一套 Agent 框架。对较复杂的非交易回复，额外请求一次无工具的模型改写；输入包含最近六条对话、当前用户要求、阶段和经过筛选的卡片事实。默认最多点名一两项，明确要求听完整选项时才展开。

语音编辑收到的是本轮重点，不是直接拿整张价格表改写。已有预算时先筛选相关候选；仅浏览时可以只传“屏幕有车型和预估费用”的信息。完整原始候选仍用于输出检查，且不修改屏幕卡片。

金额、地点和确认口令等关键交易信息由宿主组合，跳过自由改写。较短且本身适合口语的普通回答也跳过额外模型请求。改写失败、超时、格式无效、带链接／内部字段，或出现新增价格、无依据到达时间、交易成功宣称时，使用本阶段的自然简短备用表达，业务任务不因此重试。

`speech_source` 记录 `model`、`grounded`、`brief` 或 `fallback`，`speech_stage` 记录阶段。准备好的播报随展示历史保存，但“准备播报”不表示用户已经完整听到；本轮没有新增播放完成回执或改变原有打断机制。

数字、状态和表达规则不能证明所有自然语言含义都正确。本轮检查了明确的价格、时间和交易状态边界；更多口语、方言和老人实际听感仍需真人验收。

## GitHub 调研依据

- [LiveKit 基础语音 Agent](https://github.com/livekit/agents/blob/main/examples/voice_agents/basic_agent.py)：为语音单独设定简短、自然、无 Markdown 的表达要求，并区分模型与 TTS。
- [LiveKit GPT-Live 示例](https://github.com/livekit/agents/blob/main/examples/voice_agents/gpt-live/README.md)：办事结果回传后，由语音层用自己的话表达；同时明确独立委派不自动解决后续改口的问题。小瑞保留现有统一会话和消息顺序管理。
- [LiveKit pipeline nodes](https://docs.livekit.io/agents/logic/nodes/)：支持在模型与 TTS 等节点之间定制处理。小瑞借鉴分层思路，未复制上游实现或迁移运行时。

## 真实验证与复现

`experiments/speech_live_probe.py --live --audio` 使用真实豆包模型与合成接口，输入是明确标记的测试车型／价格，没有查询生活服务、创建订单或叫车。测试覆盖预算延续、明确要求念选项、改口只看看、长文本口语化；四项均取得模型改写输出，记录见 [真实播报结果](acceptance/speech-live-2026-11-05.json)。最终一次改写单次耗时约 3.1–4.3 秒，仅为本轮观测；额外改写会增加延迟和模型调用费用，不能视为稳定时延承诺。

正式 HTTP 接口也已使用全新隔离身份验证：屏幕保留五项居家活动的完整正文，播报只讲听音乐和简单活动等具体重点，`speech_source=model`，两种文本不同；没有业务事件。证据见 [正式链路结果](acceptance/speech-host-live-2026-11-05.json)。这轮总耗时 15.35 秒，包含主 Agent 与额外播报改写，并非语音首包时延。

146 项 Python 离线测试通过，其中 15 项为播报与宿主接入专项测试。覆盖重点筛选、预算延续、按要求念选项、无依据价格／时间／成功状态拒绝、失效后的备用表达、交易确认要素保留，以及屏幕与播报分别持久保存。

试听文件保存在被忽略的 `.local-data/speech-demo-2026-11-05.mp3`，开头明确说明是测试播报，其中的车型和费用不是真实当前报价。

```sh
.venv/bin/python -m unittest tests.test_speech tests.test_speech_host -v
.venv/bin/python -m experiments.speech_live_probe --live --audio
```

前端原有“听小瑞说”、语音输入模式自动播报和持续通话均继续读取 `speech_text`。历史旧消息中已存的播报不会被静默重写，新的回复使用本设计。前端订单卡片自身的简短状态通知沿用现有实现，本轮主要完成会话回复、候选引导和宿主确认方案的播报。
