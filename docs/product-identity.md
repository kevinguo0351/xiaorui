# 小瑞：产品理念与理想态

用户于 2026-11-04 确认基础理念，并于 2026-11-05 补充长期陪伴、兴趣内容和主动了解偏好的方向。正式名称：中文“小瑞”，英文“xiaorui”（小写）。本文作为项目产品定位与理想态的统一说明，实际交付状态以验收文档为准。

## 产品主张

**小瑞，让老人说句话，就能更自主地安排生活。**

小瑞是面向老年人的 Personal Agent。理想的体验是：像有一个熟悉自己、耐心可靠的年轻人在身边，听得懂日常说法，能帮助处理数字时代的生活事务，也能记得自己的习惯和兴趣，在合适的时候聊几句、分享喜欢的内容。

老人负责表达愿望和作出决定，小瑞负责理解需求、补齐必要信息、连接真实服务，并把选择与结果讲清楚。通过持续服务同一个人，小瑞逐渐减少重复询问，让每一次帮助都更贴近这个人的生活。

## 我们要解决的问题

很多老人知道自己想去哪里、想吃什么，也能自己出门、上车和取餐，但手机里的输入地址、选择车型、切换规格和付款流程成了门槛。一次线上操作的困难，可能让老人放弃见朋友、去想去的地方，或在不想做饭时订一顿熟悉的饭菜。

小瑞帮助老人完成这些线上步骤，减少对子女即时协助的依赖，保留自己安排生活的自主权。服务是否可用、费用是否能接受、线下行动是否适合，都依据实际情况确认。

日常交流也能让小瑞逐步了解这个人：喜欢什么作品和故事，什么时候愿意聊天，怎样的推荐有用。办事与交流使用同一份经过确认的个人记忆，使助手在长期使用中越来越熟悉老人。

## 理想的使用方式

**家人前期协助设置，老人日常通过语音自主使用，小瑞持续记忆、办事并适时交流。**

家人可以协助设置家庭地址、常用地点、熟悉餐厅、服务账号和必要的支付方式，也可以帮助设定主动互动的时间与频率。具体账号和支付操作遵循服务方实际支持的方式，家人设置也尊重老人的意愿。完整家庭设置流程尚未实现。

日常入口像一个熟悉的聊天联系人：可以打字、发一条语音，也可以接通持续语音通话；文字、语音和图片共享同一个人的资料与正在办理的事情。老人可以连续补充、改口或打断，小瑞承接最新意思。

语音是主要入口。小瑞根据对话环境挑重点，自然说明“现在有哪些选择、接下来可以怎么做”；屏幕保留可核对的详情。交流保持成年人之间的尊重与平等，语气耐心、简短、清楚。

## 理想态的三项核心能力

### 帮得上忙：跨过数字服务的操作门槛

- **出行**：从理解“去女儿家”，到确认实际接送点、车型与预估费用，经确认叫车，再说明真实接驾进度和车辆信息。
- **用餐**：围绕熟悉的餐厅、口味、预算和取餐方式，帮助提前点餐或送餐到家。麦当劳、瑞幸是当前接入的服务，长期扩展到老人日常愿意使用的餐厅。
- **日常提醒**：按约定提醒吃药、出门或办事。提醒计划接入苹果提醒事项 App，老人用口语创建、查询、修改或取消；服药提醒依据已经设置的内容，不自行决定药物与剂量。

涉及消费，必须讲清具体内容、地点和金额，取得确认再执行。路线查询、叫车请求、司机接单、待支付订单和支付成功分别说明真实状态。

### 记得住人：让习惯和兴趣持续发挥作用

长期记忆包括三个方面：

| 记忆类型 | 示例 | 如何帮助下一次交互 |
| --- | --- | --- |
| 稳定资料 | 家庭地址、常用目的地、熟悉餐厅 | “回家”“还是那家”能够结合已确认资料理解 |
| 日常习惯与偏好 | 饮食口味、常用预算、午饭时间、愿意被提醒的时段 | 减少重复询问，在合适的时候提出帮助 |
| 兴趣与交流偏好 | 喜欢的作品、作者、戏曲、故事或视频类型，愿意听多长 | 分享更合口味的内容，调整讲述方式与频率 |

明确要求长期保存时，要实际写入并反馈；“今天预算二十元”等临时要求保留在当前任务中。推测出的习惯先作为待确认线索，不能因为出现过一次就固化成长期偏好。

老人可以用口语查看、纠正和忘记资料。记忆应能说明来源和适用范围，并在后续任务中使用最新有效信息。当前“忘记”移除有效资料并隔离旧召回，不表示所有历史审计文件被物理擦除。

### 相处自然：在适当的时候主动交流

在老人同意的范围内，小瑞可以主动发起有目的、可拒绝的交流：

- **办事提示**：“快到午饭时间了，今天要不要帮您看看常吃的那家店？”
- **兴趣分享**：推荐老人可能喜欢的抖音视频，或聊一段他喜欢的作品里的故事；可以先简短介绍，愿意听再继续。
- **了解偏好**：“您平时更喜欢听戏曲，还是听故事？”“刚才这段您喜欢吗？以后想多听一些吗？”

这些询问自然穿插在相关情境里，一次只问一个有用的问题；老人可以不回答、换话题或结束。明确说明是长期偏好问题，并在授权范围内确认、保存和反馈，避免把聊天变成连续填问卷。

内容推荐与故事分享依赖真实、可核实的来源。抖音只是未来的内容渠道之一，具体接入方式和权限需验证；不能把生成的链接或虚构的视频当作真实推荐。讲作品时说明作品与来源，区分原作内容和自己的概括，拿不准就不编造剧情。

## 主动互动与记忆如何形成闭环

理想的循环是：**了解或询问 → 确认长期偏好 → 保存记忆 → 在适当情境提出帮助或分享 → 听取反馈 → 修正记忆与互动方式。**

例如，小瑞问过并确认老人喜欢粤剧、愿意下午听一小段，之后在允许的时段问“今天想不想听一段粤剧相关的故事？”老人说今天不想听，就结束这次提议；说“以后少推荐一点”，就调整长期频率。一次拒绝与长期不喜欢分别处理。

主动交流需要可管理的时段、频率、安静时间与暂停方式。小瑞可以主动提议，是否继续由老人决定；消费另行绑定具体方案确认。长期推荐方向以老人反馈和实际帮助为依据。

## 当前落地与后续规划

| 方向 | 当前已有基础 | 理想态仍需补齐 |
| --- | --- | --- |
| 自然语音入口 | 文字／语音切换、持续通话入口、实时转录与打断机制；正文与播报分开生成 | 真人语音、回声、方言、接话时延和老人可用性验收 |
| 生活事务 | nanobot、三平台场景工具、真实查询／核价、确认与任务记录；麦当劳独立待支付订单实验 | 网页完整交易、真实叫车与进度、送到家等逐项验收 |
| 长期记忆 | 显式资料保存、查看、修改、忘记及跨进程读取 | 兴趣和习惯的主动了解、候选记忆确认、来源和适用范围管理 |
| 主动互动 | 基础调度宿主 | 同意设置、触发条件、时段频率控制、提醒和通知送达 |
| 内容与陪伴 | 普通对话、自然口语表达 | 抖音等真实内容接入、基于作品来源的故事分享与反馈调整 |

实施顺序是：先让语音和真实生活服务稳定可用，再完善记忆与任务生命周期；随后在明确同意的范围内做主动询问、提醒和内容分享，用长期反馈验证是否更懂这个人。上述主动能力和内容渠道是产品方向，本轮仅更新文档，没有将其实现为运行功能。

首版服务仍聚焦北京的瑞幸、麦当劳、滴滴，并保留已明确授权的广州麦当劳外送只读验收范围。当前实现和历史实验细节见 [当前范围](current-scope.md)、[联系人式交流](contact-experience.md) 与 [自然播报设计](conversational-speech.md)。
